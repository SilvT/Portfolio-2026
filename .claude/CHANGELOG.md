### Fix — Phase Rail accordion content clipped on open (Bug 3)
- **Symptom:** opening a row (e.g. "Systematic Thinking Kicks In") revealed the detail panel, but its last line of text was cut off at the bottom edge — readable in the accessibility tree/DOM but visually clipped.
- **Cause:** `measure()` in `phase-rail-accordion.js` summed each child's `offsetHeight` only, which excludes CSS margins. The `<p>` tags in `.case-phase-row__detail` have `margin: 0 0 8px` (reset to 0 on `:last-child`), so the computed height was short by the uncounted margin(s) — confirmed via Playwright: children summed to 72px + 20px padding = 92px, but actual `scrollHeight` was 100px.
- **Fix:** `measure()` now adds each child's computed `margin-top` + `margin-bottom` to its `offsetHeight` before summing (still can't read `detail.scrollHeight` directly — see Bug 1 above, it's pinned to 0 while collapsed). Verified in-browser at desktop and 375px mobile widths: `offsetHeight` now equals `scrollHeight` exactly on open, no clipping, resize recompute also correct.

### New component — Phase Rail accordion variant (`.case-phase-rail--accordion`) + "The Journey" section on `case-marketing-management.html`
- **Context:** the static Phase Rail (2026-10-07 entry) only ever had the collapsed-row shape, no expand JS, because its first use case (library-freeze.html) had no secondary detail to hide. This task needed that detail: condensing the old `marketing-management.html`'s 5-phase milestone timeline (originally a `<details>`-based `.milestone` accordion, see `accordion.js`) into the Phase Rail's visual language instead, full-width as a section intro rather than the narrow `.case-pairing-row__left` slot.
- **SCSS:** added `.case-phase-rail--accordion` in `case-study-components.scss`, reusing the existing (previously unused) `&__toggle`/`&__detail` scaffold already sitting in the base `.case-phase-row` rules. Had to override the base `.case-phase-row__detail { display: none; }` back to `display: block` for this variant — see bug below. Expand transition is `max-height`, driven by a `--case-phase-row-detail-height` custom property set from JS (can't `transition` to `max-height: auto`), wrapped in `@media (prefers-reduced-motion: no-preference)` per the project's existing convention (matches `project-navigation.scss`, not a new reduced-motion mixin).
- **JS — new file `phase-rail-accordion.js`:** mutually-exclusive accordion (only one row open at a time), same pattern as `accordion.js`'s milestone behaviour but rewritten standalone rather than extended, since the markup and detail-measuring logic differ enough (new component per the project's "new components get their own file" convention). Wired into `case-marketing-management.html`'s existing inline module script, alongside Swiper/lightgallery init.
- **Bug 1 — detail panel measured as 0px height on open:** `scrollHeight`/`offsetHeight` of the detail element itself is pinned to 0 while it's still collapsed (`max-height: 0`), so measuring the wrapper directly always read 0. Fixed by summing `offsetHeight` of its children instead (`<p>` tags aren't height-constrained by the parent's `max-height`).
- **Bug 2 — same measurement still returned 0 even summing children:** turned out the base (non-accordion) Phase Rail's `.case-phase-row__detail { display: none; }` rule was still active, so children had no box at all to measure (`display:none` collapses descendants completely, unlike `max-height:0`). Fixed by having the accordion variant explicitly set `display: block` back, with `max-height`/`overflow:hidden` doing the actual collapsing instead.
- **Bug 3 — content clipped after a resize while open:** the `--case-phase-row-detail-height` value is only computed at the moment a row opens, so resizing the viewport afterwards (e.g. desktop → mobile, where text wraps to more lines) left the old, now-too-small pixel height in place and the bottom of the text got cut off. Fixed with a debounced `resize` listener that recomputes the currently-open row's height.
- **Tap target:** the toggle `<button>` alone is only 32×32px, below the 44×44px minimum on mobile. Rather than resize the button, moved the click listener onto the whole `.case-phase-row` (already had `cursor: pointer` from the base rail styles, so the affordance already implied this) — button clicks bubble up to it naturally. Added a guard (`event.target.closest('.case-phase-row__detail')`) so clicking a link inside an open row's detail panel doesn't also collapse the row.
- **Content:** condensed the old file's 5 milestone phases (01 Foundation through 05 Proving the System) down to one outcome line + one body paragraph per row, dropped the bulleted sub-lists and the 05's dedicated CTA panel (its design-system link folded into row 5's body copy instead, since the thesis statement above already links to `/case-design-system.html`).
- **Placement:** inserted between "Context: What It Replaced" and "Strengths" as the chronological bridge between the problem and its resolution, rather than at the very top — no section ordering instruction existed for this page, so chose this in the absence of a spec rather than ask up front.
- **Verified:** Playwright-checked at 375/480/767/768/769/1024/1200/1728px — no horizontal overflow at any width, row-open/row-close/mutual-exclusivity/keyboard-Enter-on-toggle/link-click-inside-open-row all confirmed working via direct DOM assertions, not just visual inspection.

### Tools grid: fixed description text overflowing card bounds on hover
- **Symptom:** Silvia spotted "The Figma Finder" card's hover description spilling out past the card's rounded corner into the preview card below, with a visible hard edge where its box-shadow border crossed the boundary.
